# 基于 Linux 边缘计算平台的多模态智能看护终端

这是一个面向竞赛重构的原型工程。它把原先依赖 `萤石云 API + Mac mini/OpenClaw` 的智能看护思路，改造成以 Linux 开发板为核心的本地感知、本地决策、离线可运行的嵌入式终端架构。

## 目标

- 将摄像头降级为辅助视频输入，不再作为唯一感知源
- 将传感器事件、视觉事件、规则决策、执行联动拆成独立模块
- 保证断网时核心检测、报警、日志能力仍然可用
- 为竞赛展示提供可运行骨架、日志数据库、状态页面和测试样例

## 当前实现

- `sensor_event` 标准事件接口
- `vision_event` 标准视觉接口
- `decision_event` 规则引擎与状态机
- `alarm_action` 执行联动接口
- SQLite 本地日志存储
- 本地 HTTP 状态页与 JSON 接口
- 传感器/视觉仿真器，便于没有实物时先联调

## 目录

- `smart_care_edge/`：主程序
- `config/default_config.json`：默认配置
- `tests/`：规则与流程测试

## 架构

1. 感知层
   - PIR、毫米波、门磁、烟雾、按键等事件进入统一总线
   - 摄像头提供视频帧/抓拍结果，作为辅助确认链路

2. 边缘推理层
   - 当前提供模拟检测器接口
   - 后续可替换为 OpenCV / YOLO / NCNN / ONNX Runtime 推理器

3. 决策层
   - 状态机：`normal / attention / warning / alarm`
   - 支持“传感器异常 + 视觉确认”与“视觉异常 + 传感器佐证”

4. 执行层
   - 蜂鸣器、继电器、补光灯、语音、截图留档、远程通知
   - 当前默认写入日志并更新本地状态，可按板卡实际 GPIO 替换

5. 数据层
   - 本地 SQLite 记录事件、决策、动作
   - 状态页展示最近事件和当前等级

## 快速运行

```bash
python -m smart_care_edge.app --config config/default_config.json
```

启动后访问：

- 状态页：`http://127.0.0.1:8080/`
- 状态 JSON：`http://127.0.0.1:8080/api/status`
- 最近事件：`http://127.0.0.1:8080/api/events`

程序默认运行一组仿真输入，用于展示：

- 日间无人
- 夜间门磁触发
- 人体存在 + 视觉确认
- 烟雾触发独立报警
- 跌倒按钮触发直接报警

## 后续接板建议

按下面顺序替换仿真模块：

1. `SimulatedSensorAdapter` -> 真实 GPIO/I2C/UART/SPI 传感器驱动
2. `SimulatedVisionDetector` -> 本地轻量目标检测
3. `ActionExecutor` 中的模拟动作 -> 实际蜂鸣器/灯/继电器/GPIO 输出
4. `CameraSnapshotProvider` -> RTSP 抓帧或萤石抓拍代理

## 与竞赛要求的对应关系

- 嵌入式深度：传感器接入、状态机、本地服务、自启动、数据库、状态页
- 软硬协同：传感器和视觉共同进入决策链，动作形成闭环
- 离线能力：规则、动作、日志、页面均可本地工作
- 可量化验证：内置事件与决策记录，便于统计误报率、响应延迟、稳定性
